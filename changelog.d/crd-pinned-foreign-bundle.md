### Added

- Maintainer extractor `crd.version-removal` 2.11.0: a reviewed exclusion of one file can pin a vendored third-party bundle by content digest (`"foreign": {"groups": [...], "sha256": [...]}`). At every release the scan checks that the file has one of the pinned digests, decodes strictly within 1 MiB without template syntax, holds only definitions of the declared other API groups and kinds that are no definition, and names no API group the project itself defines anywhere. Only then is a plain `resources` kustomization that names exactly that file no longer a reference that voids the entry; every other referrer, a kustomization with any other key, and a kustomization above a patched one still void it. The loader refuses patterns, directories, upper-case extensions, kustomization and chart names, missing or malformed digests and groups, and combinations with `copies`, `prePatch` or `defines`; the target guard lists a changed pin as a changed exclusion. No target uses it yet: rules, records and attestations change only by the extractor version and the code digests.
