### Added

- `prufyx-maintainer release-docs regen --root DIR --mode unreleased`: it regenerates the README coverage regions, the preview counts and `cli/docs/generated/coverage-counts.json`, and with `--release-blocks` (release cut) also the generated blocks of the unreleased notes file and CHANGELOG entry, with the same code the check uses, so a data change needs no hand commit. It is deterministic and idempotent, writes only inside the generated blocks and the counts file, restores the written files when it returns an error, reads no network, and refuses a root that is not the top level of a git work tree. With `--release-blocks` it needs the tags fetched and refuses a shallow clone, more than one notes file without a tag, and an untagged version that is not higher than every local version tag.
- `prufyx-maintainer release-docs check --mode unreleased --blocks-base COMMIT`: the README coverage regions and the counts file must be current, while a generated release notes or CHANGELOG block may stay as the base commit has it; any other difference in a block fails. CI passes the base commit of its event. The `release` and `cut` modes require every block to be current, as before. Rendered blocks containing raw markup, links, control characters or a `## ` heading are refused, and the command ignores inherited git settings and replace refs.
- The release-docs check requires the marker pair of the CHANGELOG `[Unreleased]` entry, when present, to be empty. An onboarding batch may change `cli/docs/generated/coverage-counts.json` only to its regeneration from the proposed data. The release notes and coverage report renderers are now gate paths.
