### Added

- `scripts/qa-auto/review_cases.py` adds permanent regression cases to every qa-auto run (stage 4d): a removal-crossing rule must not turn into exit 0 through `--knowledge-db`, the automatic store choice, `check batch` or a same-id rule in the store (driven by a Go harness behind the `prufyx_qa_review` build tag, which no normal build or test run sets); an OpenSearch experimental key removed in 3.0.0, the Falco `-m` alias and a differently cased Cortex flag must not be a bare PASS; `check cncf --native-resource` must not PASS a resource at an API version the target no longer serves. Open findings are listed in `review-allow.json` in the qa-auto state directory, each with a tracking reference and a reason. A listed case that now passes raises an alarm until the entry is removed, so the list only shrinks and an empty list is the release gate. Only the known wrong PASS is suppressed for a listed case; a crash or other exit stays a mismatch. A missing or failing Go harness and any skipped case raise an error. Adjacent removals that no rule covers yet are reported as known gaps and cannot be listed.
