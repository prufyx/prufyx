### Added

- A CRD extractor target for Knative Serving (12 CRDs in four groups: serving.knative.dev, autoscaling.internal.knative.dev, networking.internal.knative.dev, caching.internal.knative.dev) from the 0.46 line onward, tag family `v` (the `knative-v1.19` to `knative-v1.24` tags name the same commits), with line attestation enabled. Seven definition files are read from `config/core/300-resources`; five more are listed as explicit paths because upstream reaches them through symlinks into `vendor/knative.dev` and the release install artefacts are built from them. One exclusion is reviewed in the target with evidence pinned to the release tags v0.46.9, v0.47.3, v0.48.3, v0.49.1, v0.50.0 and v0.51.0: `third_party/gateway-api-latest/gateway-api.yaml`, a third-party Gateway API bundle referenced only by the end-to-end scripts, on which no claim is made. The install manifests are generated from `config/core`, `config/post-install` and `config/hpa-autoscaling`, and only `config/core` holds CRDs; the published `serving-crds.yaml` and `serving-core.yaml` of the six commits were compared with the twelve declared CRDs (names, groups, versions) and are equal, so the bundle is not part of them. A parse of every file containing a CustomResourceDefinition at the six tags found the twelve declared files and three third-party bundles (Gateway API, contour, cert-manager) only. These checks cover the knative/serving repository and its Serving install manifests, not Knative Eventing or the net-* repositories. In a dry run of the derive loop, all five pairs (0.46 to 0.47 through 0.50 to 0.51) are attestable with no removals. Attested pairs appear only after the factory re-derives them and the data change passes the QA gate and data review.

- Coverage denominators: the new table row classifies Knative as a CNCF project (catalog: cncf; the pinned CNCF landscape project list in cli/internal/cncfcheck/data/landscape-projects.json contains it), and Knative was already part of the pinned release-line snapshot, so the CNCF measure (projects, upgrades, gaps) is unchanged. Reviewed targets rise from 87 to 88 (CNCF landscape catalog 46 to 47). No pair is decided yet; the expected result from the attestation is A 5, B 0, shown only after release derivation and a data change. The registry digest changes with the table row and needs the usual maintainer approval through the onboarding batch.
