### Added

- A CRD extractor target for Traefik (group traefik.io, ten kinds) read from the aggregate definition file in the upstream reference documentation, from 3.2 onward, with line attestation enabled. Two exclusions (a legacy-group definition file and the integration-test fixtures) are reviewed in the target with evidence pinned to the release tags v3.2.5 to v3.7.18; the fixtures hide one Traefik-owned CRD (traefikproxies.gateway.traefik.io, gateway operator test manifest) on which no claim is made. In a dry run of the derive loop, all five pairs (3.2 to 3.3 through 3.6 to 3.7) are attestable with no removals. Attested pairs appear only after the factory re-derives them and the data change passes the QA gate and data review.

- Coverage denominators change with this target. The new table row classifies Traefik as a community project (catalog: community) because it is not in the pinned CNCF landscape project list (cli/internal/cncfcheck/data/landscape-projects.json has no traefik entry; the table requires an upstream entry exactly for a community project). As a result the CNCF measure loses one project and five gap pairs (79 to 78 projects, 395 to 390 upgrades, gaps 302 to 297) and the community measure gains them (18 to 19 projects, 88 to 93 upgrades). Decided counts are unchanged. The higher CNCF percentages are a denominator change, not new coverage. Decided pairs from the Traefik attestation (expected: A 5, B 0) appear only after release derivation and a data change.
