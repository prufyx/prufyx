### Added

- The `target-draft` rules file may carry an optional `pathFilter` list next to `installPaths`: anchored globs (the only wildcard is `*` inside one path segment; `**`, `?`, brackets and braces are refused), each with a reviewed reason, evidence and a required `expectFiles` (the exact number of files the entry matches at every tag, a positive integer pinned from reviewed evidence; a rules file without it is refused, and a different count is the stop `path-filter-count-mismatch`). A definition file under the chosen install paths that matches an entry is not read as the target; it is reported in report.json as a filtered copy (path, groups, tags, sorted and counted) and is part of the facts digest. An entry that matches nothing at a tag is the stop `path-filter-matches-nothing`. A filter never hides an unreadable file (the unreadable-shape stop stays). A filtered file is allowed only when every group it defines is a reserved or Kubernetes group or has a known other owner in the ownership index; a group the target reads or the index lists for this project is the stop `filter-hides-owned-group`, and a group with no single known owner is the stop `filter-hides-unowned-group`. Control characters and invalid UTF-8 in globs and install paths are refused when the rules file is read, and the facts digest quotes any such value. Also, `pathFilter` without `installPaths` is refused when the rules file is read. A rules file without `pathFilter` produces the same output as before.
