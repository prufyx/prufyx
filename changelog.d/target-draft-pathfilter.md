### Added

- The `target-draft` rules file may carry an optional `pathFilter` list next to `installPaths`: anchored globs (the only wildcard is `*` inside one path segment; `**`, `?`, brackets and braces are refused), each with a reviewed reason and evidence. A definition file under the chosen install paths that matches an entry is not read as the target; it is reported in report.json as a filtered copy (path, groups, tags, sorted and counted) and is part of the facts digest. An entry that matches nothing at a tag is the stop `path-filter-matches-nothing`. A filter never hides an unreadable file (the unreadable-shape stop stays) or a file that defines a group the target reads (the stop `filter-hides-owned-group`), and `pathFilter` without `installPaths` is refused when the rules file is read. A rules file without `pathFilter` produces the same output as before.
