### Added

- Maintainer extractor `crd.version-removal` 2.12.0: a target may declare a generation kustomization (`"generation"`): a kubebuilder kustomization whose build output is committed under a listed path and whose own resources are not in the tree. Its directory becomes a declared definition directory, so the patch fragments below it (annotation and conversion patches of one definition) are read, each only by its bytes and only for a definition of the listed paths; the declaration decides no version. A reviewed exclusion of one `.cue` file can pin a read-only source by content digest (`"pinned": {"sha256": [...]}`): the file is an excluded finding of reason `pinned-source` while its digest holds, no template syntax and no `apiextensions.k8s.io` text, and void otherwise; the pin relaxes only the `//go:embed` check of the install-surface guard. The loader refuses malformed declarations and pins, and the target guard lists an added or changed declaration or pin. KubeVela uses both: the pair 1.8 to 1.9 is expected to give four `crd.version-removal` rules (core.oam.dev v1alpha2 of Application, ApplicationRevision, ComponentDefinition and TraitDefinition) once the factory re-derives it; no rule, record or attestation changes at merge except the extractor version and the code digests.
