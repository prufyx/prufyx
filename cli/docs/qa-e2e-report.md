# QA report: runs on kind clusters

[`generated/qa-e2e.md`](generated/qa-e2e.md) (and `generated/qa-e2e.json`) list the results of Prufyx runs against real upgrades on kind clusters. For each run it shows the Kubernetes versions, the kind node image digests, the Prufyx commit and, for each app, the upgrade that was tried; for each check it shows what Prufyx said against what the oracle (a replay on the target cluster, or an in-place upgrade) observed, as one of four forms: `correct`, `wrong PASS`, `false alarm` or `gap`, with a reason code and the digests of the log and inputs. The report is display only: kind is not production fidelity, the runs do not change any Prufyx verdict, and no knowledge package or CLI output carries them. The counts say how many runs and rows exist; they do not say that every version or every project was covered, and a `gap` is a row where Prufyx made no claim the oracle could be compared with. The files are generated by `prufyx-maintainer qa-report --results-dir DIR --out cli/docs/generated/qa-e2e.json --md cli/docs/generated/qa-e2e.md` from the run result files, which stay outside this repository; the command reads them through a closed schema (an unknown format, field or reason is refused), copies only an allowlist of fields (no host names, addresses, paths, user names or free text), and with `--check` exits 1 when the committed files differ from the regeneration.
